测试绑定这两个接口的源地址。`pktmon` 只匹配这两个 IP，并在物理 NIC 层采集：Realtek 下层组件117快照记录 RX 3,445,562,713 字节、TX 3,872,064,463 字节，Intel 网卡也记录了测试收发。Realtek 上下层是同一批包，未重复合计。

64 MiB 环形抓包保留尾部，导出组件117后独立解析到35,829个匹配测试地址的以太网帧，包含双向 TCP、UDP、ICMP；帧的源/目的 MAC 与上述两张物理网卡一致。因此本轮有实际出入物理网口的证据。抓包不是全程包数，不能拿环形文件的包数直接计算全程丢包率。CPE具体型号、固件和中间桥接拓扑未确认。

Windows `Get-NetAdapterStatistics` 在主矩阵前后记录的增量为：WLAN RX 3,816,665,185 / TX 3,424,280,073 字节；以太网 RX 3,493,110,742 / TX 3,880,957,065 字节。独立检查72项原始采样轴，均落在相应网卡的前后累计计数之间。总网卡计数还包含背景流量，不能与工具负载字节强行相等。

## CTS限制与后续验收缺口

CTS TCP部分状态行在相同接收时刻成批到达，例如原始TimeSlice约9～11秒的行在事件12.054秒批量出现；工具自身TimeSlice和产品接收事件时间不是同一个时钟。当前实现不会从缓冲输出猜测完整正式窗口，因此保守保留NOT_EVALUATED。六项不是无流量，也不能算正式速率通过。

后续需要解决CTS实时事件时间证据/缓冲问题并复测完整窗口，同时补齐CTS四个RX分布字段；仍缺IPv6、默认完整预设与正式长时压力矩阵、第二台Windows及CPE内环控制覆盖。此前验收方案的全部父项未据此改成PASS。
