# v6.3.2 补充问题回归

基线：已发布 v6.3.1。用户追加核对双向 iperf3 失败提示和导入项目缺失网口。

确认原因：

- `IPERF_EXEC_FAILED` 与 `IPERF_PREFLIGHT_FAILED` 原来共用“windows未设置iperf3环境变量”的处置建议。执行失败、端口冲突、用户中断和 agent 能力不足均可能被误说成工具未安装。现分开提示，保留原始原因及判定码。
- 导入把集合标为手工集合，旧协调逻辑只标失效不清理；候选为空时连标记也跳过，成功连接后没有自动重校验。

修复行为：已知快照下移除缺失网口对及空集合/绑定，保留套件配置并提示；未知或扫描失败保留为待校验并随草稿保存。角色和端点别名兼容后端规则；保留有效 pair ID、端点顺序和绑定子集。

自动回归覆盖：

- iperf3 已可用的双向任务通过工具预检；运行失败提示原始端口占用证据，不再断言缺少工具。
- 缺失网口清理、零候选但扫描已成功、未知拓扑保留、旧失败快照不清理、连接成功自动校验。
- 显式绑定子集清空不能扩大为全选；角色/大小写别名可匹配，方向与 pair ID 不变。

完整回归结果在发布 CI 中验证。真实 Windows 双机/CTS 与线速测试未在本轮执行。

本地完整回归通过：前端 272/272、Rust 687/687、fmt 与本机/Windows MSVC 严格 Clippy。浏览器实际导入含缺失主控网口的项目，看到网口对及空集合的移除提示。
