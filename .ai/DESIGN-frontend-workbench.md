## 1. 用户来这里要完成什么

这是一台双机网络测试仪的工作台。高频用户需要尽快判断：两端能否开始测试、这轮具体跑什么、当前是否需要介入，以及结束后去哪里拿结果。页面围绕这四个问题组织。

| 使用情境 | 首先需要知道 | 最直接的下一步 |
| --- | --- | --- |
| 第一次进入 | 主控网卡是否识别、工具是否可用、辅测机是否连接 | 连接辅测机，或修复具体缺项 |
| 日常重复测试 | 上次计划是否仍适合当前网卡、这轮用什么参数 | 导入/调整计划，预览并开始 |
| 测试运行中 | 正在跑什么、进度是否仍更新、哪些单元需处理 | 定位单元、查看原因，必要时停止 |
| 测试结束或隔天回来 | 哪一轮、结果文件是否存在、能否复测 | 打开/下载报告，装载原计划后重新预览 |

导航保留“本机、辅测机、测试计划、执行、进度、监控、历史运行”七个入口，按“测试流程”和“工具与记录”分组。已有术语和入口先保持稳定，不新增一张重复汇总的首页。

辨识度来自**双端链路关系和清晰的测试对象**：主控/辅测的端点标识、方向连线、当前单元的仪表读数、对象列表中的统一状态。视觉资产优先使用内联 SVG 的网口、Wi-Fi、主机及链路图；只画数据确实表达的关系，不虚构 CPE 内部拓扑，不加入装饰性照片。

## 3. 视觉系统

### 3.1 颜色与主题

沿用深青作为品牌色，减少厚重灰底和多重边框；状态色只表达实际状态。以下改为已恢复的实际色值，作为后续统一入口；全面对比度验收后再做针对性调整，不平行维护另一套色板。

| Token / 用途 | 浅色 | 深色 |
| --- | --- | --- |
| `--canvas` 页面背景 | `#EDF1F3` | `#0A0F12` |
| `--surface` 主工作区 | `#FFFFFF` | `#141C20` |
| `--panel-2` 次级分区 | `#F3F6F7` | `#101A1E` |
| `--ink` 正文 | `#15222B` | `#E7F0F1` |
| `--muted` 辅助文字 | `#536671` | `#9CAFB5` |
| `--line` 分隔线 | `#CCD6DC` | `#2A393F` |
| `--accent` 品牌/主操作 | `#0E5A6B` | `#3FB9CA` |
| `--on-accent` 主操作文字 | `#EEFBFD` | `#05161A` |
| 成功 / 未达标 / 待处理 | `#12783E` / `#B3242F` / `#C8811A` | `#6ECF95` / `#FF969B` / `#FFC65C` |

主题支持跟随系统、浅色、深色；`color-scheme` 必须跟随当前选项，避免深色页面出现浅色原生选择器。正文、禁用、焦点、选中、悬停分别校验；普通文字目标至少 4.5:1，大字和必要的控件边界目标至少 3:1。

状态必须同时有文字，不能仅靠红绿：通过、未达标、仅测量、未评估、准备失败、已跳过。上述颜色表记录当前值，不是可访问性合格证明；例如浅色 `--focus` 作为小字使用时必须另测对比度，必要时拆出更深的告警文字色。详情保留原始 `PASS`、`RATE_FAIL` 等代码。`MEASURED` 不显示绿色通过标记；未知值显示“未知状态”和原值，不能自动归入成功。

### 3.2 字体、密度与层次

- 使用 Windows 系统字体 `Segoe UI / Microsoft YaHei`，macOS 回退 `PingFang SC`；不下载字体。
- 页面标题 24px/32px，分区标题 15px/22px，正文与主要控件 14px/22px，辅助信息 12px/18px。避免把重要参数缩到 10px。
- IP、端口、数值和日志用系统等宽字体；普通标签用正文字体。数字启用 tabular-nums，带单位并对齐小数/右边界。
- 间距采用 4、8、12、16、24、32px。分区间 24px，字段间 12–16px，紧密相关的标签与输入框间 6–8px。
- 桌面行高以 40–44px 为基线；触摸操作热区约 44px。小图标可为 16–18px，但点击区不能同样缩小。
- 圆角：小标签 3–4px，控件 6px，浮层 10px。连续分区用留白与分隔线；只有浮层需要轻阴影。
- 主界面不堆叠卡片，不把每个数字装成 KPI 卡，不用渐变、发光和粗描边区分所有层级。

### 3.3 动效与视觉资产

采用成熟组件的反馈节奏，不搬运整套营销动效。

| 交互 | 目标反馈 | 约束 |
| --- | --- | --- |
| 按钮悬停、选中 | 100–140ms 颜色/边框变化 | 不缩放按钮、不改变宽高 |
| 浮层打开、关闭 | 120–160ms opacity，可选 2–4px transform | 不推动正文；焦点立即可用 |
| 切换详情 | 原位置替换内容，保留选择标记 | 不强制等待退场，不自动滚回顶部 |
| 保存、复制、连接 | 固定位置文字确认，状态同步变化 | 成功态不能造成按钮宽度跳变 |
| 加载 | 静态占位、按钮“连接中…” | 无旋转图标、闪烁骨架和持续呼吸灯 |
| 曲线、吞吐、进度 | 只按实际采样/响应更新 | 不补帧、不做数字滚动或伪平滑 |

上述时长是后续交互组件的上限建议，不要求所有控件添加动效；当前恢复版本没有动效也不构成缺陷。实现只使用短 `transition`；现有 `@keyframes` 全局禁令保持。`prefers-reduced-motion: reduce` 下关闭这些过渡。持续动画、视差、光束、粒子、模糊背景和鼠标跟随均不进入测试工作台。

## 4. 成熟组件选型及适配方式

**选择：参考 shadcn-vue 的源码组件结构，复杂交互使用 Reka UI，外观接入本仓库 CSS tokens。** 不迁移 React，不批量安装完整 UI 模板，也不为少数组件立即改造全站 Tailwind 构建。

- shadcn-vue 提供可放进项目自行维护的 Vue 组件；当前文档涉及 Reka UI 和 Tailwind。按组件取用并改写样式，不直接运行会覆盖现有配置的初始化命令。[项目介绍](https://shadcn-vue.com/docs/introduction)
- Reka UI 提供 Vue 的无预设样式交互基础，可使用普通 CSS 适配；组合式组件用于焦点、键盘和弹出层行为。[介绍](https://www.reka-ui.com/docs/overview/introduction)、[样式指南](https://www.reka-ui.com/docs/guides/styling)
- Aceternity UI 的相关组件面向 React/Next.js、Tailwind 与 Motion。本项目借鉴 Stateful Button 的反馈与可展开详情的层次；不引入 React/Motion，不使用背景光束或浮动 Dock。[组件目录](https://ui.aceternity.com/components)
- Magic UI 的安装路径面向 React 组件体系。本项目仅借鉴精细状态反馈；数字翻滚、跑马灯不适合灌包测量。[安装说明](https://magicui.design/docs/installation)
- 本次访问 Origin UI 地址跳转到 coss ui。可参考对象列表、表单行、筛选工具条，但实施时按当时实际组件检查 Vue 可用性、依赖和许可，不把 React 示例直接复制进 Vue。[当前入口](https://coss.com/ui)

上述选型已用 Context7 `/unovue/shadcn-vue`、`/unovue/reka-ui` 与官方网页交叉检查。现有工具名为 `query_docs`，对应仓库规则中的文档查询步骤。**依赖具体版本在实施阶段锁定，本方案不宣称完成兼容性验证。**

| 本项目组件 | 采用/参考 | 使用位置 | 适配重点 |
| --- | --- | --- | --- |
| `UiButton`、`UiField`、`StatusBadge` | shadcn-vue Button/Field 的组合方式 | 全站 | 原生语义，固定加载尺寸，错误关联，tokens |
| `UiTabs` | Reka Tabs | 计划工作区、运行详情 | 方向键，选中与焦点分离，保留面板状态 |
| `UiCombobox` | Reka Combobox | 大量网卡、套件、配置 | 输入搜索、无匹配、清空、键盘选择 |
| `UiMenu`、`UiTooltip` | Reka DropdownMenu/Tooltip | 次要操作、图标说明 | Escape、焦点返回，不能只在 hover 提供重要信息 |
| `UiDialog` | Reka Dialog / shadcn-vue 结构 | 删除影响确认、导入冲突 | 标题、焦点陷阱、取消、返回原操作点；无毛玻璃 |
| `ObjectList`、`DetailPane`、`InlineNotice` | 本仓库 Vue 展示组件 | 计划、历史、网卡详情 | props in / emits out，不读取 state/API |
| 图标 | 统一一套本地内联 SVG；可按需取 Lucide Vue 图标 | 导航与对象类型 | 单一描边风格；核对许可、显式导入、无外链 |

Reka 示例可能含 `@keyframes`，shadcn 示例可能含动画类、外部字体或不适用的默认路径；全部删改后才纳入。第一批仅引入实际使用的 Tabs、Dialog 等组件，比较前后 HTML 体积和浏览器运行成本，避免一次迁入整个目录。普通表格、按钮、静态提示不为“使用组件库”而增加依赖。

## 5. 页面与操作闭环

### 5.1 全局外壳

```
┌ CPE 子网测试控制台        辅测连接状态  运行状态/查看进度  主题 ┐
├ 测试流程 ───┬ 页面标题、当前上下文                 主操作 ┤
│ 本机        │ 简短说明 / 必要的连接或数据更新提示            │
│ 辅测机      ├ 对象搜索、筛选、当前选中对象                  ┤
│ 测试计划    │ 连续工作区                                  │
│ 执行        │ 对象列表         │ 就地详情 / 编辑器           │
│ 进度        │                  │                           │
│ 工具与记录  │                  │                           │
│ 监控 / 历史 │                                              │
└─────────────┴──────────────────────────────────────────────┘
```

每页只有一个最突出的主动作，危险动作独立呈现。连接状态与“浏览器能否取得最新数据”分开：辅测未连接不等于浏览器离线。未读到运行状态时显示“运行状态待同步”，不要直接显示“空闲”。

导航按区域记住搜索、选择和滚动位置；从“编辑参数”进入配置详情，再点“返回任务”，返回原套件、原任务和滚动处。第一版采用 `state/ui.ts` 的显式上下文，不引入路由库；不写 token 或敏感配置进 URL。详情关闭、取消和返回都是可见操作，浏览器后退不作为唯一出口。

### 5.2 本机：先回答准备好了没有

信息顺序：双端连接概况 → 工具与版本一行摘要 → 网卡列表。主操作随实际条件为“连接辅测机”或“配置测试计划”。

网卡搜索支持名称、描述、IP、角色；列表保留接口名、IPv4、角色、协商速率。选择一行，在详情区展示网关、IPv6、完整描述和可复制 IP。320–767px 用列表与详情切换，详情顶部提供“返回网卡列表”；不要把六列挤到手机上。

本机加载时只显示“正在读取本机信息”；失败保留明确错误与“重新加载”；已确认缺少 iperf3 才提示安装位置，并准确说明受影响的是使用该工具的任务。未知协商速率显示“未获取”，不能写成 0 Mbps。

### 5.3 辅测机：连接、核对、继续

地址/端口一行，共享令牌一行，前缀过滤一行。帮助写在相应字段下，操作区为“连接”。令牌默认 password，可显示；输入值与 bootstrap 回填不互相覆盖。

成功后在连接区原位显示对端身份与网卡数，出现“配置测试计划”。保留修改连接设置入口。未连接时网卡区说明下一步；连上但无匹配网卡时明确指出主控还是辅测端，并指向前缀字段。重新扫描使用当前表单前缀，显示扫描结果和完成时刻。

扫描失败保留上一份网卡并标记为上次成功数据；不能把旧数据继续伪装成刚扫描成功。仅提示对应失败，不把所有网络异常归为令牌错误。

### 5.4 测试计划：围绕对象组织，不把用户锁进向导

保留三个工作区：**分配链路与套件 / 编辑套件 / 编辑流量配置**。它们可随时切换，不编号为必经步骤。页头保留导入、导出、恢复默认；“预览与执行”为主操作。

```
测试计划                                    [预览与执行]
[分配链路与套件] [编辑套件] [编辑流量配置]
搜索链路 / 跨机·同机筛选               已分配摘要（单行）
链路集合                    基线套件  稳定性套件
主控网口 A ↔ 辅测网口 B         ☑          ☐
主控 Wi-Fi ↔ 辅测 Wi-Fi         ☑          ☑
```

- 分配表：固定集合名称列，横向滚动仅发生在表内；扩大单元格勾选区，表头全选显示三态。搜索只控制可见行，不改变配对、绑定或链路范围语义。表头整列操作继续作用于全部链路集合，明确标注范围；搜索结果不缩小它的作用域，规则见 §11.1。
- 套件：左侧可搜索对象列表，右侧选中套件与任务。任务显示真实执行顺序；协议、方向、IP 版本为紧凑字段组，门限/覆盖为就地展开。排序按钮保留，拖拽不是唯一操作方式。
- 配置：左侧搜索与协议筛选，右侧名称、适用协议、参数。修改共享配置前显示真实引用它的任务；不凭字符串名称推测引用。
- 点击任务“编辑参数”保存返回来源；返回后字段与选择不丢。删除选中对象后选择相邻对象，列表空时显示创建入口。
- 延续当前即时编辑与草稿机制，不增加实际上无效的“保存”按钮。只有确认 localStorage 写入成功才显示“草稿已保存”；失败提示本次修改尚未持久保存。
- 导入失败保留旧计划；恢复默认/删除展示影响范围和取消入口。禁止原生 prompt/confirm/alert。

```

运行设置  时长 / RESUME / 截图 / UDP 限流
高级设置  全局默认档位 / Wi-Fi 门限 / 按网口策略（就地展开）
─────────────── 计划复核 ───────────────────
[预览/重新预览]  单元数、预计耗时、预计跳过（单行摘要）
套件 / 任务分组列表             选中单元的参数、门限与来源
───────────────────────────────────────────
已复核当前计划 / 需要重新预览                  [开始测试]
```

开始按钮旁说明为何暂不能开始：尚未预览、预览已过期、预览失败、正在启动或已有运行。参数改变仍由现有 `previewIsCurrent` 和服务端计划 hash 把关。数量、耗时、RESUME 预判、最终门限只读服务端结果。

点击开始期间禁用重复提交，成功进入进度；失败保留计划和表单，就地重试。停止操作显示在运行状态附近，文案按实际停止行为确认，不虚构“立刻停止所有进程”。高级字段保持原值和继承语义，不把未知留空改成 0。

### 5.6 进度：先看当前任务，再定位需处理的单元

顶部为当前单元/阶段、已完成数、剩余估计、停止入口；进度条下方放文字，避免跨双色背景阅读。统计改为一条可点击筛选：全部、未达标、未评估、准备失败、通过、仅测量、已跳过。筛选行固定放在列表前；窄屏可换行或局部横滚，不恢复为独立大数字卡。

主体为可搜索单元列表与选中详情，搜索序号、标题、链路和原因码；不从日志推断状态。详情只展示 `UnitStatus` 已有的标题、判定、原因、耗时与链路等字段。**当前进度 DTO 没有每单元 RX/P10/目标值；需要这些证据时引导打开报告，不能凭空补数字。** 如后续要在线展示，必须另列 DTO 与后端任务。

日志放在独立可展开区，保留当前 4000 行上限；用户向上阅读时停止跟随，有新日志时显示“回到最新”。搜索只搜已加载日志并说明范围。轮询失败后显示上次更新时间和“连接暂时中断，正在重试”，不清空已完成项、不改成结束/失败判定。

结束后主操作切换为“打开报告”，次操作为“历史运行”。已中止、正常结束、报告尚未就绪分别说明，不用一个成功提示覆盖所有终态。

### 5.7 监控：对象列表和选中曲线

顶部保留主控/辅测、网卡、采样间隔、开始监控；左侧会话列表显示网卡、端点和状态，右侧显示选中曲线。保留全部开始/停止的批量入口以及既有会话上限；可按需提供对比布局，避免默认把所有大曲线无限向下堆叠。

RX/TX 同时用文字、线条样式和颜色区分；无样本显示“等待首个样本”，真实 0 显示 0，断流留空档。保留原有 `RateChart` 和 `monitor-chart` 算法，不为更平滑的画面制造采样点。

停止、启动失败、已达上限、无可选网卡各有对应提示；切详情不新建监控、不重置样本。最新数值提供可读文本，使键盘用户不依赖图上悬停。

### 5.8 历史运行：找得到、拿得走、能返回

列表按当前后端信息提供搜索：运行目录 ID/时间、报告是否存在、是否有原计划。右侧详情展示目录名、修改时间、文件可用性、体积和操作。**`RunEntry` 没有设备、通过率、失败数或测试状态，第一版不提供这些筛选，也不把 modified 当作精确测试开始时间。**

下载归档、恢复报告、重新执行分别保留；只有 `has_request` 才提供重跑。恢复期间显示具体运行目录与进度反馈，结束后刷新该条记录并维持选择。重新执行装载原计划后进入预览，不自动开始；明确 RESUME 选择。

无记录引导进入执行；搜索无结果提供清空筛选；加载失败可重试。返回列表保留查询和滚动位置。当前没有“获取归档报告摘要”接口，详情不能悄悄发明接口或读取本地任意文件。

### 5.9 辅测状态页与导出报告

主控七页完成后，再做伴随页面的一致性批次：`src/agent/webui.html`/`webui.rs` 的只读状态页，以及 `src/report.rs` 及其实际模板/生成模块。沿用字体、状态文字、表格密度、窄屏详情与附件入口。

它们不是 Vue 构建入口：辅测页保持只读，离线 HTML 报告保持完全自包含、类型化数据与附件兼容。无需把它们迁成 SPA。具体模板入口在实施前沿 `write_report` 确认，避免根据历史文档改错文件。

## 6. 统一的状态与业务边界

| 状态 | 界面行为 | 明确禁止 |
| --- | --- | --- |
| 首次加载 | 静态占位 + 读取对象名称 | 预先显示缺失、0、空闲或失败 |
| 已有数据刷新 | 保留数据，标记更新中；失败注明上次成功时刻 | 反复清屏或闪烁 |
| 对象为空 | 对象级原因 + 可执行入口 | 所有页面统一一句“暂无数据” |
| 搜索无匹配 | 显示查询与清空入口 | 把真实数据删掉或改动选择 |
| 表单错误 | 字段附近提示，关联 aria-describedby | 仅顶部 toast、丢失输入 |
| 网络中断 | 留住旧数据与更新时间；维持原重试节奏 | 自动重发开始/停止/删除等命令 |
| 控制台鉴权失效 | 全局提示重新用完整地址打开 | 混为辅测令牌错误，或无尽轮询 401 |
| 操作成功 | 在发起位置确认，保留上下文 | 只闪一下 toast 就消失 |

离线运行指本地/局域网服务无需互联网，不等于必须支持服务已关闭时首次加载网页。不新增 Service Worker 缓存带口令页面。运行新鲜度来自现有请求成功/失败时刻，不使用 `navigator.onLine` 判断辅测是否在线。

补充状态字段可放在 `state/session.ts`、`state/run.ts`，例如 `loading`、`lastSuccessAt`、`refreshError`；它们表示前端观测，不进入配置与判定 DTO。使用原 `setTimeout` 链，不新增定时器、不提高请求频率。初始运行状态可做一次快照读取，必须与已有轮询共用出口并防并发；后续显示未知直到同步，不能从前端默认值推断服务器状态。

## 7. 响应式、键盘和性能验收

- 1280px 及以上：常驻侧栏，对象列表约 260–300px，详情使用余下空间；内容不无限拉宽。
- 768–1279px：侧栏缩窄，主从比例自适应；先保护编辑区最小宽度。
- 320–767px：紧凑横向主导航；对象列表与详情分屏切换，明确返回；大矩阵保留独立可聚焦滚动容器和固定标识列。
- 长主机名、IPv6、错误消息、中文缩放到 200% 时，不能撑破整页或隐藏主操作；吸底操作条必须预留空间，不能盖住最后一行。
- Tab 顺序与视觉顺序一致；方向键操作真正的 Tabs/Combobox；Enter 激活，Escape 关闭浮层并归还焦点。普通按钮组不伪装 listbox。
- 新增跳转主内容入口；图标按钮有名称；更新提示用局部 `role=status`，日志不设整块 assertive live region。
- 维持原轮询频率、日志上限与采样策略。对 1000 个完成单元、4000 行日志、最大允许监控会话做实际操作测试，记录选中/搜索耗时与 DOM 数；确有瓶颈才加分页或虚拟化。
- 搜索基于已有数组，先测成本再决定节流；不能每敲一个字请求服务端。过滤函数放 `domain/`，保留对象稳定 ID、执行顺序和未显示项。

## 10. 始终保持的边界

- 运行时离线、单 exe 分发，全内联，无 CDN、外部字体、额外网页子资源；不得放宽鉴权/CSP。
- `components/` 不读 state/API，`domain/` 不依赖 Vue；请求仍走唯一 API client。
- 默认 Windows 档位、配置继承、计划 ID、端口、RESUME、方向和频段稳定键不因设计改变。
- 判定由现有唯一实现产生；不把 TX、丢包、工具状态等诊断二次叠加成性能判定。
- 新的详情/搜索基于真实已提供字段；需要新数据时单独列协议工作，不能靠标题字符串推断。
- 不加持续动画或更密轮询，不替换原图表的数据算法，不自动补发有副作用的请求。
- 按用户要求分批实施，不自动提交、推送、发布或升级版本。

## 11. 最终交互约定（后续实施须遵守）

本节明确前文容易产生分歧的细节，不是当前已实现能力。新增状态仅用于界面，不改配置格式、协议字段或判定算法。

### 11.1 搜索、筛选与批量操作

第一版只做页内搜索，不增加全站命令面板。搜索框始终提供名称与清空按钮，placeholder 不能代替标签。采用大小写不敏感的字面量匹配；去除查询首尾空格，多段空白分隔的词必须各自匹配该对象至少一个可搜索字段。IPv6、点号和括号按普通字符处理，不作为正则表达式。输入法组合输入结束后再更新结果。

| 对象 | 搜索字段 | 默认列表顺序与选择 |
| --- | --- | --- |
| 网卡 | 接口名、描述、IPv4、IPv6、角色、所属端 | 沿用后端/现有 inventory 顺序；不改变业务端点引用 |
| 链路集合 | 集合名及真实成员的端点名/IP/角色 | 沿用集合顺序；不修改 bindings |
| 套件/配置 | 名称、协议；套件可匹配任务名 | 维持任务执行顺序；搜索不重新编号执行任务 |
| 预览单元 | 序号、标题、已有 trace/最终参数/门限文字 | 服务端 `seq` 顺序；重新预览后重新核对选择 |
| 已完成单元 | 序号、标题、链路、判定、原因码/原因详情 | 当前 `run_id` 内按 `seq`；到达新单元不抢选中项 |
| 历史运行 | 完整目录 ID、返回的修改时间文本 | 沿用现有列表顺序；明确展示“修改时间” |

搜索计数写“显示 8 / 42 项”。搜索无匹配时保留输入，提供“清空搜索”；真实对象为空时提供连接/创建/运行入口，两个空态不混用。状态筛选与文本搜索取交集，查询不发请求、不使计划预览过期。

**分配表的表头复选框继续作用于全部集合。** 有查询时工具条明确写“整列操作影响全部 N 个链路集合，当前显示 M 个”；三态值也按全部集合计算。局部行勾选只影响该行，清除查询不撤销已勾选的项。第一版不再新增“仅选择可见行”批量按钮，避免同一页面并存两种全选语义。

现有“全部/跨机/同机”会参与链路集合协调，不是新搜索的别名：保留其原业务含义和消费者。新的名称查询绝不能调用 `reconcile()`。已绑定的集合因真实拓扑变化而失效时走原 stale 提示，不能通过搜索把它们悄悄删除。

### 11.2 对象选择、详情与返回

```
套件列表 → 选中套件 → 展开任务 → 编辑共享配置
   ↑                           │
   └──── 返回该套件的该任务 ────┘
```

- 选择按 ID 保存：套件/任务/配置使用现有 id；历史使用运行目录 id；监控使用 session id；完成单元用 run_id + seq。网卡展示使用所属端与现有接口身份，不能把新 UI 下标写入业务端点。
- 进入跨工作区详情时记录来源区域、工作区、套件/任务 id、查询、展开项、滚动与触发按钮；“返回任务”恢复这份上下文。若来源已删除，返回其列表并说明对象已不存在，不选择同名对象冒充原对象。
- 查询隐藏了当前对象时，保留详情并提示“当前对象不在搜索结果中”，提供清空搜索；不悄悄切到第一条。首次打开有对象时可选第一条，无对象显示空态。
- 用户明确删除选中对象后才选择原位置的下一项，末项则选上一项；刷新导致对象消失时显示“该对象已不存在”，由用户选择下一项。长运行中新数据到达不能抢焦点或清掉输入。
- 桌面使用同页主从布局；窄屏进入详情后用“返回列表”。断点变化时保留同一对象与编辑值，不重新挂载后丢失草稿。不用模态弹窗承载长参数编辑器。
- 当前页面切换由 `v-if` 卸载视图，需保存的纯界面上下文放 `state/ui.ts`，不为保留状态把所有页面常驻 DOM。滚动恢复在相应内容渲染后进行；不能把焦点移进隐藏区域。
- 同一次页面会话内保留查询、选择和返回来源；刷新后默认恢复已有计划草稿与主题，页面级浏览位置可重置。第一版不新增导航持久化或浏览器历史路由，也不存令牌/连接配置到新的偏好记录。

### 11.3 编辑、草稿与共享配置

当前采用即时编辑。切套件/配置或返回列表不回滚已经有效的更改；“返回”不写成“取消”。删除确认中的“取消”只取消删除，不能撤销此前编辑。

输入中的暂时无效字符串（例如未输入完的数值）留在字段草稿中，显示就地错误；不能立刻把它截断、归零或写入业务对象。离开对象前若仍有无效字段，保留该字段并指出问题，允许用户显式放弃该字段草稿；不要误导用户以为它已用于本轮计划。导出、预览、开始需要有效值时，提示定位首个无效字段。

有效计划变动继续沿用现有 500ms 草稿写入节奏。显示三种反馈：“修改待保存”“草稿已保存”“草稿未保存，请导出项目备份”。只在实际 `localStorage.setItem` 成功后显示已保存；失败不阻止本次有效编辑，不添加持续重试定时器。主题仍沿用原存储方式。

共享配置详情显示“被 N 个任务引用”，展开可看到真实任务名称与所在套件，点击可定位任务。对共享配置的修改即时影响所有引用，不伪装成当前任务的私有覆盖；复制/解绑遵循已有业务函数，不在这轮额外发明参数继承层。

导入与恢复默认按以下顺序处理：校验输入 → 列出将替换的范围 → 用户确认替换 → 一次落地 → 使旧预览失效。导入校验失败、取消替换时原项目原样保留。删除配置/套件时列出受影响的真实引用；确认与取消都有可聚焦按钮，不使用原生对话框。

### 11.4 连接身份、网卡快照与数据新鲜度

连接表单草稿、最后成功连接的身份、最后成功扫描的网卡是三类信息。修改地址时，顶部不能立即把旧连接显示为新地址；成功响应落地后才更新“已连 …”。失败后若保留旧网卡，必须显示旧地址与上次扫描时刻，并标注为旧快照。

| 情况 | 应展示的信息 | 对计划操作的影响 |
| --- | --- | --- |
| 本机工具请求成功、辅测未连 | 本机工具与网卡；辅测待连接 | 保持现有同机/跨机业务能力，不新增统一连接门禁 |
| 本机工具请求失败、双端连接成功 | 连接回包的两端网卡；本机工具“未获取，可重新扫描” | 不因工具摘要未知隐藏拓扑；具体可执行性由预览/后端决定 |
| 新地址连接失败，有旧快照 | 新请求的错误 + 旧快照的身份/时间 | 旧快照可查看，不作为新连接成功或新预览有效的证据 |
| 扫描成功，无符合前缀的网卡 | 明确是哪一端为空及当前前缀 | 指向前缀/网络排查，不能写成未连接 |
| 重扫失败 | 保留最后成功数据并标旧 | 不自动执行 reconcile 到空拓扑，不凭失败抹掉用户意图 |

本机请求和 bootstrap 独立展示失败；一个成功不能覆盖另一个错误。无更新时间时显示“尚未同步”，绝不填入页面打开时间。使用已有响应事件更新绝对时间文本，不为“几秒前”另起计时器。

### 11.5 预览、开始、停止与不确定响应

展示状态与设备判定分开。以下是前端操作状态，不新增服务端 Verdict。

| 操作状态 | 按钮和说明 | 允许的下一步 |
| --- | --- | --- |
| 未预览/预览中 | “预览”或“预览中…”；开始禁用 | 预览只读，不启动测试；重复点击不并发 |
| 预览成功且当前 | 可“开始测试”；展示最终参数与门限 | 开始携带当前 plan_hash，保持原后端复核 |
| 预览过期 | 保留上次结果但标明过期；开始禁用 | 重新预览；不能通过取消错误提示恢复旧 hash |
| 启动提交中 | 固定尺寸“启动中…”并防重复提交 | 保留原计划，等待响应 |
| 启动请求超时/断联，结果未知 | “尚未确认是否已启动，正在同步运行状态” | 通过原状态读取出口核对；不能自动再发一次开始 |
| 启动已确认 | 进入进度并显示真实 run_id | 不根据按钮点击时刻虚构当前单元 |
| 停止提交中/已受理 | “正在请求停止”/“已请求停止，等待收尾” | 继续获取状态；禁止把HTTP成功直接当成整轮结束 |
| 停止结果未知 | 原运行和最近数据仍显示，操作注明未确认 | 先同步运行状态；不能仅凭超时认定已停止 |

只有状态读取已确认没有正在运行的任务，才重新开放人工开始；若无法确认则保持“待同步”，提供重试读取而非重发命令。当前 DTO 没有请求幂等键，不宣称能精准证明某次超时请求从未执行。开始、停止、报告恢复、计划装载的异步结果都必须绑定发起时的对象，不写入后来选中的别一条记录。

首次运行状态读取与已有轮询共用进行中的请求，不另开一条轮询链。普通读失败保留游标与样本，后续按原间隔重试；控制台鉴权失效进入全局终态并停止反复401。错误信息显示当前对象、失败动作和可用下一步，不能通过日志内容推断判定。

同一个页面会话只允许一个会替换计划的操作进行（导入、恢复默认、历史重跑装载）；忙碌期间禁用冲突操作，下载和查看详情可继续。第一版不增加任务队列或自动排队重试。

### 11.6 进度、日志、监控与历史详情的细节

进度页的总判定数来自服务端 counts；列表只显示已收到的单元。若两者暂未对齐，分别注明“服务端汇总”与“已载入 N 个单元”，继续同步原游标，不据列表长度重算服务端通过数。换 run_id 时清空旧运行的列表筛选上下文和选择；同一轮增量保留。

日志默认跟随最新。用户向上滚动后暂停跟随；新日志到达只显示“有新日志 / 回到最新”，不抢滚动位置。折叠日志不停止原有同步，也不扩大4000行缓存。被缓存上限淘汰的行不能继续显示为可搜索；提示“仅检索最近已加载日志”。

监控切换选中会话只换展示，不能重新 start/stop；监控停止后的现有回收与移除语义在实施前核对，不能让新详情面板阻止会话释放。图表的 RX/TX 图例点击只改变可见线条，不改变采样源、会话数或上报数据。视图未选中也不降低其他会话已约定的采样频率。

历史详情第一版只展示 `RunEntry` 已有信息。已存在报告仍可重新生成；没有结果明细不提供恢复；没有原计划不提供重跑。操作失败只显示失败，不点亮“报告可用”标记；恢复成功后再读取列表确认。

“打开报告”沿用现有主控打开文件的行为，并在该操作附近说明“在主控机打开”。远程取回使用“下载包”，不能把它改写成浏览器中直接打开报告。下载不能在发起时就显示“文件已保存”；当前无法观测落盘时，只能说明已发起或等待浏览器下载。

### 11.7 组件与页面的实施边界

| 所在层 | 负责 | 不负责 |
| --- | --- | --- |
| `domain/` | 字面量筛选、可见列表、已有效对象的纯派生 | Vue、网络、浏览器存储、DOM、重新判定结果 |
| `state/ui.ts` | 当前选择、返回来源、查询、展开项、滚动与焦点恢复描述 | 持有第二份业务计划、第二份网卡、第二条轮询 |
| session / run / monitor state | 请求生命周期、最后成功数据、新鲜度、错误和防重入 | 通用按钮/弹窗的布局 |
| `components/` | 接收对象和状态，发出选择/返回/提交意图 | 直接读state、fetch、解析外部日志作业务结论 |
| `views/` | 组合对象、权限/状态提示、调用既有业务入口 | 复制配对、判定、配置继承算法 |

Reka 组件只解决复杂交互行为；基础按钮、输入、状态条保持清晰的原生结构。组件接入必须能单独回退，不要求改完全部页面才可构建。引入 Portal 的浮层要确认 CSS tokens 在挂载位置仍有效，关闭后焦点回到触发点；对嵌套控件和暗色原生表单一起验收。

开发期可以使用明确标注的 fixture 观察布局；生产源码里不保留演示数据回退、演示控制按钮或“接口失败就显示假数据”的路径。视觉资产只用真实端点、协议、方向与状态构成，不能让连线动画暗示未测量的流量。
