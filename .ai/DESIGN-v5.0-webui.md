# DESIGN v5.0 · 控制台前端重写

> 分支：`feat/webui-vue`　基线：`b3013e6`（main, v4.6.0 之后）
> 目标：把手写的 `src/master/webui.html`（3519 行 / 117 个顶层函数 / 25 个可变全局）
> 换成 Vue 3 + Vite 构建产物，并**重做信息架构**，因为后续所有执行都走「快速工作台」。
> 合入策略：分支上跑够真实测试（用户口径：至少一个月）再并回 main。

---

## 1. 目标与非目标

**目标**

1. 消掉一整类 bug：手工 DOM 同步导致的「重渲染吃掉光标 / 吃掉点击」「筛选和自动分组用了两套谓词」。
2. 重做信息架构，让高频路径变短。高频路径是**导入项目 → 核对 → 跑 → 盯 11 小时进度 → 看报告**，
   不是「从零拼链路集合」。当前布局把这条路径的入口全放在五步向导的最底下。
3. 让运行进度对得起一次 11.5 小时的测试——现在它只有一个日志窗口。

**非目标**

1. **不重画视觉。** 现有皮肤（「机箱是安静的拉丝钢，数据屏是刻框暗玻璃 + 磷光信号色」，
   零持续动画因为机器正在灌线速）是有据可依的设计，不是随手写的。CSS 变量体系原样搬过去。
   要改的是**布局与流程**，不是配色。
2. 不动任何 Rust 侧的判定、执行、报告语义。
3. 不动 CSP，不动鉴权模型。
4. 不引入路由（`vue-router`）——这是个单页工具，标签切换用状态就够，加路由等于给
   「鉴权先于路由」再开一个需要考虑的面。

## 2. 为什么是换框架，而不是继续修

这一轮修的六个 UI 问题里，有四个是同一个根因：

| 现象 | 根因 |
|---|---|
| 点「按角色自动分组」没反应 | 渲染用 `PAIRS.filter(p => p.cross)`，分组用另一份谓词，两处漂了 |
| 同机组合没被勾上 | 同上，`qroleKey` 还把同机/跨机塌成一个键 |
| 改集合名字时光标被吃 | `input` 事件里调 `renderQuickSets()` 重建 innerHTML |
| 点「收起网口对」不收起 | `qset-expand` 只会展开，因为展开态存在 DOM 上而不是数据里 |

修法分别是：抽一个 `qcandidatePairs()` 当唯一筛选源、给角色键加前缀、
`input` 里只改状态不重渲染、把展开态挪进数据。
**这四个修法在响应式框架里是默认行为**：computed 天然唯一，v-model 不重建节点，
`v-if` 读的就是数据。继续手写就是继续按人头去堵这一类。

另外两个（整列勾选、UDP `-l` 列）是纯功能，跟框架无关。

规模佐证：JS 2869 行、CSS 360 行、`render*()` 家族靠 innerHTML 重建。
`renderQuickSets()` 这一轮从 O(n²) 改成 O(n) 是手动把 `candidateSet` 提出循环——
computed 缓存本来就该干这个。

## 3. 选型

**Vue 3 + Vite + `vite-plugin-singlefile` + TypeScript，不用 Pinia，不用 vue-router。**

### 为什么 Vue 3

- SFC + `<script setup>` 的可读性适合这个场景：面板多、每个面板状态不复杂、
  但面板之间共享一份计划数据。
- 预编译后不需要 `'unsafe-eval'`。**Vue 完整版（含运行期模板编译器）需要 `eval`，
  Vite 预编译后不需要**——这是能不能用的分界线，选型时已实测：

  | 形态 | 在生产 CSP 下 |
  |---|---|
  | Vue 完整版 + 模板字符串 | ❌ `EvalError: … 'unsafe-eval' is not an allowed source` |
  | Vue runtime-only + 外链 `<script src>` | ❌ 脚本压根没加载 |
  | Vue runtime-only + 全内联 | ✅ 正常渲染，焦点保持，DOM 节点复用 |
  | Preact + htm + 全内联 | ✅ 同上 |

### 为什么必须全内联（`vite-plugin-singlefile`）

Vite 默认产物是 `index.html` + `assets/index-xxx.js`。**在这个控制台上跑不起来**，
原因不在 CSP 而在鉴权：`http.rs::handle()` 是先鉴权再路由，token 校验在所有分支之前。
浏览器不会给 `<script src>` 带自定义头，所以那个请求是裸 GET。实测：

```
GET /assets/index-abc.js   → HTTP 401
GET /                      → HTTP 401
GET /?token=cpetest        → HTTP 200
```

把 CSP 改成 `script-src 'self' 'unsafe-inline'` 不解决问题——CSP 是第二道门，第一道是 token。
要让外链方案跑起来还得三选一，三条都不划算：

| 做法 | 代价 |
|---|---|
| 给 asset URL 拼 token | HTML 是编译期常量，token 运行期才知道，得在 `page_response()` 里做替换 |
| `/assets/*` 免鉴权 | 在写进注释的「鉴权先于一切」不变量上开口子，还要加白名单和路径校验 |
| 改 Cookie 鉴权 | 动整个认证模型，牵连 agent 侧 Bearer 语义 |

换来的是 code splitting 和懒加载——对一个内网单页工具**零价值**。
`vite-plugin-singlefile` 的成本是 `vite.config.ts` 里一行。

### 为什么上 TypeScript

`src/master/webui/model.rs` 的注释写着「前端按这些字段名读写，改一个名字就是一次前后端同时的变更」。
现在这句话没有任何机器保证。TS 把 UI 计划 DTO 声明成 `types/plan.ts`，
字段名漂移在构建期就红。

### 为什么不用 Pinia

只有一份计划状态、没有 SSR、没有多路由。`reactive()` + 几个 `stores/*.ts` 模块够了，
少一个依赖少一份构建期风险。

### 为什么不是 Preact + htm

也过 CSP（已实测），体积更小（16.5 KB vs 106 KB）。但体积在 50 MB 预算下不是变量，
而 Vue 的 SFC + 官方工具链对「以后 AI 代理来改」更友好——单文件组件的边界比
htm 模板字符串清楚得多。

## 4. 构建链

```
ui/
  package.json  package-lock.json  vite.config.ts  tsconfig.json
  index.html                  # 只有 <div id="app"> 和入口 script
  src/
    main.ts
    types/plan.ts             # 对齐 webui/model.rs 的 DTO
    api/client.ts             # 14 个端点 + token 处理，唯一 fetch 出口
    stores/{conn,plan,run,monitor}.ts
    components/**/*.vue
    styles/tokens.css         # 从现有 webui.html 原样搬的 CSS 变量
```

```
npm ci && npm run build   →  ui/dist/index.html（全内联）
                          →  拷到 src/master/webui.html，一起提交
cargo build                  从不跑 Node
```

**CI 增一个 job**（对齐 `build_config_docs_bundle.py` 已有的逐条目字节比对模式）：
固定 Node 版本 → `npm ci` → `npm run build` → 和仓库里的 `src/master/webui.html` 比对，
不一致就红，报「前端产物与源码不同步，请重新构建并提交」。

> **风险**：跨机器的 Vite 产物字节一致性依赖 Node/esbuild 版本完全一致。
> 用 `npm ci` + CI 里钉死 Node 版本可以做到，但这是**待验证项**，不是已知事实。
> 兜底方案：字节比对若被证明脆弱，降级为「构建能过 + 产物含 `id="app"` +
> 产物零外部引用」三条断言，把「是否最新」交给一条人工检查清单。

## 5. 界面重新设计

### 5.1 现在的问题（逐条有据）

1. **两套编号打架。** 页面是 1–5 的向导，但「本机」不编号且常驻，第 3 步内部又有
   自己的 1·2·3·4。走快速工作台的人看到的是「3 · 测试计划 → 1 · 链路集合」。
2. **高频入口埋得最深。** 「导入测试项目」是回头用户做的第一件事，
   现在是第 4 步里的第三个 ghost 按钮，前面隔着三步向导。
3. **参数有两个来源。** 第 4 步有全局 `duration` / `ping 次数` / `ping 包长`，
   而套件里每条 TCP/UDP 配置也有自己的参数。谁覆盖谁，界面上看不出来。
4. **进度页配不上 11.5 小时的测试。** 只有一个日志窗口：没有单元级进度、
   没有 PASS/FAIL 计数、没有 ETA、没有失败清单。
5. **一切都在一条长滚动条上**，靠 `.hidden` 显隐。焦点和滚动位置反复出问题。

### 5.2 新的骨架

左侧常驻导航栏 + 右侧单区域填满视口、内部滚动。顶部一条细头，放**项目名 + 连接态 + 运行态**。

```
┌────────────────────────────────────────────────────────────┐
│ CPE 测试台   [项目：全量 TCP/UDP/PING ▾]  ●已连 10.228.46.50  ○空闲 │
├──────────┬─────────────────────────────────────────────────┤
│ 本机   5 │                                                 │
│ 辅测机 ✓ │            当前区域（内部滚动）                  │
│ 计划 210 │                                                 │
│ 执行     │                                                 │
│ 进度     │                                                 │
│ ──────── │                                                 │
│ 监控     │                                                 │
└──────────┴─────────────────────────────────────────────────┘
```

- 导航项带**实时状态角标**（网口数 / 已连 / 单元数 / 运行中 x/210），
  取代「第几步」的编号。编号消失，因为它本来就不是严格线性的。
- **项目下拉进顶栏**：新建 / 导入 / 导出 / 另存。当前项目名一直可见。
  这条把问题 2 直接解决。

### 5.3 快速工作台（重点）

从「四个面板挤在一个 grid 里」改成**三栏 master-detail，右栏常驻复核**：

```
┌─ 链路集合 ────┬─ 选中集合的网口对 ──────────┬─ 分配与复核 ──────┐
│ ▸ 跨机 千兆   │ [筛选: 全部|跨机|同机] [搜索]│ 套件 × 集合 矩阵  │
│   跨机6 同机0 │ ☑ A:eth0 ↔ B:eth0   跨机   │ ┌───┬───┬───┐    │
│ ▸ 同机 环回   │ ☑ A:eth0 ↔ B:eth1   跨机   │ │   │基线│PING│    │
│   跨机0 同机4 │ ☐ A:eth0 ↔ A:eth1   同机   │ │千兆│ ☑ │ ☑ │    │
│ [+ 新建]      │ …                          │ │环回│ ☐ │ ☑ │    │
│ [按角色分组]  │ [整列 ☑] [反选] [清空]      │ └───┴───┴───┘    │
│               │                            │ 210 单元 · 11.5h │
│               │                            │ ⚠ 2 条提示        │
└───────────────┴────────────────────────────┴──────────────────┘
```

关键改动：

- **右栏常驻**。现在「改左边、滚到下面才看到影响」；改完就地看到单元数和耗时变化。
- **「按角色自动分组」先预览再落盘**：弹出「将生成 3 个集合：跨机 千兆(6) / 跨机 WiFi(2) /
  同机 环回(4)，是否替换现有集合？」。这一轮它「没反应」的投诉，一半是因为它默默
  生成了但没选中——有预览就不会有这种歧义。
- **筛选是三态单选（全部 / 跨机 / 同机）**，不是一个「只显示跨机」的复选框。
  复选框的默认值语义这一轮已经翻过一次车。
- 集合名 `v-model` 直接绑，不存在光标问题。
- 网口对超过一定行数时虚拟滚动（全量预设是 10 对，还不需要；但角色分组后可能上百）。

### 5.4 计划复核

现在是一段文本。210 个单元读不动。改成**三级可折叠树**，默认折到第一级：

```
▾ 跨机 千兆（6 条链路 · 126 单元 · 6.8h）
  ▾ TCP（36 单元 · 1.8h）
      A:eth0 → B:eth0   -w 256m -P 8   180s
      B:eth0 → A:eth0   -w 256m -P 8   180s
      …
  ▸ UDP（54 单元 · 2.7h）
  ▸ PING（36 单元 · 2.3h）
▸ 同机 环回（4 条链路 · 84 单元 · 4.7h）
```

每行显示**最终下发的参数和方向**（方向读 `Unit.direction`，不读 `Leg.tag`——
单向单元的 `Leg.tag` 是空串，这是执行侧的约定）。

### 5.5 执行

把第 4 步现在混在一起的三类东西拆开：

- **运行参数**（时长 / ping 次数 / ping 包长 / 裁剪 / resume / 截图）单独一块，
  并且**标注它和套件参数的关系**：套件里写了的以套件为准，这里是没写时的兜底。
  （问题 3。当前界面完全没表达这一点。）
- **导入导出**上移到顶栏项目菜单（问题 2）。
- **开始测试**是这一区唯一的主按钮，旁边直接显示「将执行 210 单元 · 预计 11.5 小时」。

### 5.6 进度（改动最大）

```

[████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░]  22%

  #31  A:eth0 → B:eth2  TCP   NOT_EVALUATED   采样覆盖率 0.71 < 0.95
```

- 失败清单是这一页最有价值的东西：11 小时的测试，人真正要盯的是「有没有开始出错」。

- 日志屏折叠但保留，样式不动。

### 5.7 监控页

原样迁移。canvas 示波器、8 路上限、7200 点上限、颜色表全部照搬。
这一页现在没有已知问题，迁移目标是**零行为差异**。

## 6. 测试策略迁移

`src/master/webui/tests.rs` 里有 4 个测试函数、27 处 `PAGE_SOURCE`，
直接在手写 HTML 里搜标记串（`function qroleKey(`、
`<input type="checkbox" id="qcrossonly">只显示跨机链路`、`qset-rename` 等）。
**产物一压缩，这些全部失效。**

替换方案分两层：

**A. 源码层断言**（保住原来的意图：把交互入口钉死在源码里）
Rust 测试改成用 `env!("CARGO_MANIFEST_DIR")` 走 `ui/src/` 读 `.vue`/`.ts` 源文件，
断言的对象从「HTML 里有这个 id」变成「组件源码里有这个绑定/这个函数」。
例：`autoLinkSets` 的候选源必须是 `candidatePairs`，角色键必须含 `cross`。

**B. 产物层断言**（新增，防的是构建链本身出问题）
- 产物零外部引用：搜不到 `src="http`、`href="http`、`<script src=`、`<link rel="stylesheet"`。
  **这条是 CSP + 鉴权不变量的机器保证，比 A 层重要。**
- 产物含 `id="app"`。
- 产物体积上限（比如 1.5 MiB），防止有人不小心内联了 source map。

**C. 前端自己的测试**
Vitest + `@vue/test-utils`，只测这一轮出过 bug 的三块纯逻辑：
`candidatePairs` 筛选、`roleKey` 分组、单元数/耗时估算。
不做端到端，不引 Playwright——这是内网自用工具，投入产出不成正比。

## 8. 相邻的两个 Rust 侧工作项

这两项跟前端重写正交，可以并行，也可以先在 main 上做完再让分支跟上。

### 8.1 速率分位数的展示口径（已确认）

- **中位数、P95 从展示层全部拿掉**——`report/diagnostics.rs` 里的
  「网卡 RX 中位数」「网卡 RX-P95」两项。它们不参与任何判定，纯展示。
- **P10 只能不显示、不能不算。** 它是承重的：
  `rate_window` 用 `p10_mbps.is_some()` 当「5 秒滚动窗口是否完整」的信号，
  它决定 `RATE_WINDOW_COVERAGE_LOW → NOT_EVALUATED`；
  `verdict_assembly` 用 TX P10 判 `offered_shortfall_explains_rx`。
  处理：把 RX-P10 / TX-P10 从**概览表和明细表的列**里拿掉，
  保留在逐行的「诊断详情」块里——因为 `RX_P10_BELOW_TARGET` 这个失败原因码
  必须有数字佐证，否则 FAIL 说不清。

### 8.2 Excel 汇总报告

需求：跑完生成 `runs/<run>/summary.xlsx`，按**链路组**看结果。HTML 报告直观不了统计。

- 依赖 `rust_xlsxwriter`（实测 +0.95 MB，50 MB 预算下无所谓）。
- `Row` 增 `src_side` / `dst_side`；`TestSpec` 增 `link_group`。
- **链路组的取值优先级**（用户明确要求）：
  1. UI 快速工作台的**链路集合名**（用户自己起的名字，最有意义）
  2. 没有时（命令行 / 高级矩阵）回落到物理网口对
  3. 都没有时用 `role_a ↔ role_b`
  不要用主机名——实测 Arch 那台自报 `UNKNOWN-PC`。
- 四张表：总览 / 吞吐结果 / Ping 结果 / 异常处置。
- 数值必须写成数字单元格（不是字符串），冻结表头，加自动筛选，FAIL 行条件格式。
- **生成失败只能警告，不能让整轮测试的收尾失败。**
