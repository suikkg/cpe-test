# 内环测试方案重设

日期：2026-09-09。状态：**已按本文完成实现**（第 8 节第 1–5 步），真机双向与兜底验收待补。本文记录目标与约束，不替代现有实现说明和真机验证记录。

## 1. 结论与范围

内环与子网保持相同的配置、选择、预览、执行、进度、结果交互，以及可共用的底层测试语义；两者的项目配置、连接状态、运行状态、停止信号、历史记录和报告目录继续独立。

内环不是简化的“固定上下行跑两次”功能。它应支持本机独立测试、选用辅测机、多网口队列、单向和真正双向并发、TCP/UDP 参数集合、明确的接收速率来源及完整结果追溯。

设计先行、实现随后：第 8 节的落地顺序已按序完成，逐项对照见第 10 节。**代码里已有的行为仍然只算「已实现」，不等于「已在真机上验收」**——双向并发、工具兜底和多机型统计接口的真机证据要另外补。

## 2. 与旧实现的差距及落地状态

| 项目 | v1 的实现 | 本方案要求 | 落地 |
|---|---|---|---|
| 无辅测机 | agents 允许为空，但扫描会访问所有配置的 agent | 独立的「本机 / 辅测机」选择；未被本轮链路引用的 agent 不参与连接门禁 | `Link::enabled` + `InnerConfig::referenced_agents`；`probe` 分 `Ready/Failed/NotParticipating` 三态 |

| 进度 | 行数计数 | 按测试单元计数；双向一个单元含两腿，结果可筛选分页 | `UnitRow.legs`；`InnerResults.vue` 按判定/网口筛选并分页 |

## 3. 拓扑与连接

### 3.1 本机独立

主控持有 ADB，同时使用本机选中的网卡打流。不需要启动 agent，也不要求先去子网页连接辅测机。本机 iperf3、所选网卡和 ADB 就绪即可开始。

配置保留但未启用的辅测机不扫描、不连接、不阻断本轮。不能因为用户上一次测过远端网口，这次拔掉辅测机就无法测试本机。

### 3.2 本机和辅测机混合

每条链路绑定“电脑标识＋接口身份＋源 IP”。可选择本机、一个或多个辅测机。只检查本轮实际引用的电脑，分别记录可用、失败、未参与状态；连接失败保留配置，不删除用户选择。

主控通过 ADB 管理板侧 iperf3。数据由网口所在电脑直达板侧 LAN 地址；主控不必具备每条被测 LAN 的网络路由。使用已有 agent client、monitor 和定向资源回收协议。

选择空链路、同一电脑/接口/IP 重复项、失效 IP、不可用工具、错误网关归属均在预览前明确提示。不自动改系统路由，不自动改板侧权限，不静默选择多台 ADB 中的一台。

## 4. 方向、协议和执行队列

方向术语与子网一致：

| 页面名称 | 含义 | 板侧角色 |
|---|---|---|
| 上行 | PC → CPE | server 接收 |
| 下行 | CPE → PC | 板侧 client 发送，PC server 接收 |
| 双向并发 | 同一链路同时上行和下行 | 两腿同时运行，各自明确接收端 |

勾选“上行＋下行”表示两个单向测试单元；勾选“双向并发”表示一个含两腿的测试单元。允许三项全选，分别获得单向和并发结果。不能用两次顺序单向伪装双向。

外层始终按用户排定的网口顺序串行：网口 → 协议/参数配置 → 方向 → 重复轮次。只在双向单元内部并发；不同网口不同时灌包，避免桥计数器混流。页面预览、执行器、进度和报告必须消费同一份计划，不能各自计算笛卡尔积。

双向初始实现沿用子网两腿调度语义：板侧与 PC 各启动本次专用的一套 server，双方各启动普通 client 向对端发送，共同就绪后起流。两腿具有独立 job/端口/原始输出，使用共同有效重叠窗口计算双向表现。一腿失败必须停止对向、回收本单元并明确显示哪一腿失败。

板侧支持 --bidir 不意味着直接替换即可：不同版本的双向 JSON 字段、并发统计和 agent 的流事件解析都需适配。原生 --bidir 可作为后续经等价验证的执行优化，不能改变页面语义。

TCP/UDP 支持共用配置加协议专属参数：时长、并行流、TCP 窗口、UDP 每流带宽、报文长度、窗口、丢包诊断门槛；参数含义、单位、非法输入提示与子网一致。复用参数编辑和验证纯函数，板侧能力不支持的组合提前说明。不能为了板侧系统差异修改原来的 Windows 子网预设。

双向门限与单向门限分开：可选逐方向门限或接收速率合计门限，明确采用哪一种，不从单向门限自动除以二；与子网现有双向合计规则对齐。不同协议可覆盖目标。重复轮次和失败处理在预览中明确，不能悄悄重跑直到获得 PASS。

## 5. 紧凑页面

左侧仍为单独的“内环测试”。内部使用与子网一致的“设备与网口、测试计划、执行与结果”结构，不要求跳到子网页完成前置步骤。

设备配置默认折叠已就绪的 ADB 和辅测机详情。网口选择用一张表：

| 选择 | 顺序 | 电脑 | 网卡/类型 | 源 IP | 板侧 LAN | RX 接口/策略 | 状态 | 操作 |
|---|---|---|---|---|---|---|---|---|
| 复选框 | 1 | 本机 | ETH | 地址 | 地址 | 自动/指定 | 待检查 | 编辑 |
| 复选框 | 2 | agent1 | Wi-Fi | 地址 | 地址 | 自动/指定 | 就绪 | 编辑 |

- 扫描结果支持按电脑、网口类型筛选和搜索，批量勾选；导入但暂时未发现的网口保留并标缺失。
- 选择/取消参与和删除配置分开，临时不测不会丢掉参数。
- 批量设网关、测量策略和门限；不同电脑的源 IP 不能误批量复制。
- 顺序提供上移/下移操作，拖动可选，键盘也能完成。排序后的顺序写入配置和报告。
- 只展开当前编辑的一条，使用右侧详情面板；窄屏使用单条编辑页并保留返回位置。
- 表格限高并有固定表头，默认显示约 8–10 行；几十条链路不会撑长整个页面。结果分页/筛选，保留已完成项。
- 计划预览显示参与网口数、单元数、双向腿数、估算时间、接收端及门限来源；配置改变后旧预览失效。
- 执行中锁定本轮快照，可切换查看设备/计划/进度，导航不能丢失选择或生成第二条轮询链。
- 状态读取继续响应完成后排下一次，保持既有频率；无持续动画、外部资产或额外定时扫描。

## 6. 接收速率与兜底

### 6.1 默认原则

优先使用**可信的接收接口字节计数**，以保持与子网网卡 RX 口径一致。同时保留 iperf 接收端统计作为独立测量证据。字节计数记录接口流量，工具统计记录测试流的应用接收吞吐，两者不是相同层次的数值，不能简单取较大者，也不能无提示共用一套门限。

上行接收端在板侧，下行接收端在所选电脑；双向分别记录两端 RX。不按“谁运行 client”推断谁接收。UDP offered 速率、sender 速率以及最后一行 interval 都不能充当 receiver 汇总。

### 6.2 板侧接口与计数读取

拆分 LAN 地址归属与 RX 采样接口。LAN 地址用于 server bind 和目标校验；RX 接口用于统计，可以是经过确认的桥、物理成员或逻辑接口，不强迫统计接口自身持有这个 LAN IP。

自动发现接口、桥成员关系、地址和计数能力，列出候选；存在多义性时标记待指定。不能默认累加 br0 与 eth1，那可能重复计算同一批包。也不能仅凭物理接口名称认为它比桥接口更可信。

标准读取可支持 /proc/net/dev 与 /sys/class/net/<iface>/statistics/rx_bytes、tx_bytes。前者适于一次读取多个接口；后者可作为标准路径不可用时的兼容读取。它们通常来自同一套驱动统计，**换路径不能保证修复硬件卸载导致的漏计**。厂商私有统计需要具名适配器和明确单位/计数位宽，不能开放任意远端 shell 字符串作为配置。

将“读取成功”与“统计可信”分开。可信度检查覆盖接口归属、单调计数、复位/回绕、样本覆盖率、有效时间窗口、持续冻结、背景流量和已知设备差异。持续冻结并有可信非零工具接收是计数器不适配证据；单纯 RX 低于门限不是证据。异常比例提示只作诊断，不能自动择优改判。

### 6.3 三种测量策略

| 策略 | 行为 | 用途 |
|---|---|---|
| 网卡计数严格模式 | 按可信接收接口字节计数；无效时 NOT_EVALUATED | 与既有子网正式验收一致；旧配置迁移默认保持此策略 |
| 网卡优先，工具兜底 | 计数可信时使用计数；计数不可用/已判不可信时才使用有效工具 receiver 结果 | 不同 CPE 的兼容测量；新建内环配置推荐 |
| 工具接收速率 | 明确使用工具 receiver 结果；字节计数若可用则并列诊断 | 已知计数器不适配的机型 |

兜底整条方向腿选择一次统计来源，不把前半段网卡样本与后半段工具 interval 拼在一起。必须记录 source、原来源失败原因、工具/版本、接口、原始数据和测量质量。两路都无可信结果就 NOT_EVALUATED，不能拿发送端代替接收端。

工具结果优先解析可核实的结构化 receiver 汇总；旧板侧使用经过版本样本验证的文本 receiver 汇总。多流须使用明确 SUM 或同方向各流接收字节/时间的正确聚合，不能取最后一个流。获取 client 返回的 server 结果失败时，可读取本次独占 server 原文，严格确认本轮/端口/方向；日志片段或损坏 JSON 不能“猜”速率。

### 6.4 兜底与门限的关系

现有仓库的正式规则限定为 NIC RX；新方案不能将工具速率填入虚假的网卡样本、coverage 或 P10，再调用原规则获得 PASS。

因此结果保留两个层面：

1. **NIC 验收**：继续调用原 evaluate_rx_acceptance，字段语义和封闭结果不变。计数不可信仍为 NOT_EVALUATED。
2. **本次内环测量**：标明实际来源。工具兜底有速率但没有明确的工具口径门限时只标 MEASURED，并提示 NIC 验收未形成；不得继承 NIC 门限后自动 PASS。用户明确配置工具门限时才形成带“工具口径”标识的内环验收结果。

支持工具口径正式门限需要作为内环新增架构决策落地，集中在独立纯策略层选择来源和来源匹配的门限，比较/聚合逻辑集中实现，禁止散落在执行器、页面和报告。子网 NIC 验收入口的约束及旧配置语义不变。工具错误、UDP 丢包、TX 负载、掉速诊断也不能在判定后再覆盖结果。

双向合计只能相加相同来源层次的两端接收速率；一腿 NIC、一腿工具不能直接合计。计数合计不可用时，可单独提供两腿都可信的工具合计及工具门限结果；缺一腿就不能给出完整双向合计 PASS。报告同时保留逐腿结果，不能只展示总和。

## 7. 实现边界与兼容

- 内环单独 builder 生成类型化计划，executor 只消费计划；设备适配、采样、测量策略、报告与 WebUI controller 分层，避免继续把逻辑堆入 inner/mod.rs。
- 共用子网的 agent 协议、iperf 参数验证、事件窗口纯函数、NIC 统计、判定聚合和可复用的 UI 展示件；不创建第二套相同算法，不将内环塞进子网的全局配置和会话。
- 本机与 agent 实现相同的 PC 执行接口；ADB 实现板侧控制/采样接口；工具计量与 NIC 计量分别产出带来源的测量类型。
- 内环项目继续独立 kind；新 schema 明确升级为 version 2。旧 protocol 迁为 protocols，旧 upload/download 数组保留顺序单向语义，不能迁为 bidir。未知新版本拒绝导入，迁移失败不改当前配置。
- 端口、job、owner、ADB 临时目录逐任务唯一；双向中任一腿的启动/停止异常都做定向回收。只清理本次资源，回收无法确认则停止队列。停止一次作用于整个内环单元及其两腿。
- 内环与子网同控制台互斥运行以避免抢占链路；取消信号、配置、历史和结果独立。断线/重连不得触发自动再开跑；刷新应恢复当前实际运行状态。
- 内环历史留在 inner_runs，可查看、导出与按原配置重新生成计划；重跑生成新记录。恢复/跳过能力必须以稳定计划 ID、配置/来源/门限/设备身份为匹配条件，不能套用子网 RESUME 数据。
- 报告沿用子网的汇总、单元、方向、协议、参数、门限、实测速率、诊断和原文布局；新增来源/兜底原因。HTML/JSON/API 同源。无对应样本的工具统计不能伪造网卡分布和覆盖率。
- 能力检查包含 PC/板侧工具、LAN 地址、端口和 agent 版本；连通性失败单独记录，不能直接归为速率失败。是否继续其他独立网口可配置，默认先完成预检并明确不可执行项。
- 平台不支持的功能明确禁用。ctsTraffic 的板侧端点不可照搬 iperf；IPv6、CTS 等未适配能力不得因界面复用了子网组件而显示为可执行。截图仅在支持的电脑端提供，不能把 ADB 文本冒充截图。

## 8. 落地顺序及验收

1. **模型与兼容**（已完成）：链路启用、电脑引用、方向/两腿、独立 RX 接口、策略/来源门限；v1 → v2 迁移及计划预览。计划由 `inner::plan` 单独产出，页面、执行器、进度和报告消费同一份。
2. **界面**（已完成）：批量网口表格、详情面板、排序和单元预览；表格限高固定表头，窄屏退化为单列。
3. **执行**（已完成）：无 agent 路径、只连接被引用 agent、单向与并发两腿、共同有效窗口、逐腿端口与资源目录、取消/回收。
4. **测量与报告**（已完成）：两条计数读取路径、独立统计接口、严格 receiver 解析、来源选择与门限、双向同源合计、逐腿结果详情与 `inner_runs` 独立历史。
5. **回归**（已完成）：原子网测试与导入导出原样通过；`cargo fmt --check`、`cargo test --locked`、本机与 `x86_64-pc-windows-msvc` 两目标严格 Clippy、前端 `vue-tsc`/测试/构建/`verify` 产物一致性全部通过。

必须覆盖的行为：

- 没有任何 agent，以及配置了离线但未启用 agent，均可跑本机。
- 本机/辅测机混合网口严格按预览顺序执行；取消后不启动下一条。
- 上行、下行、两次顺序单向、真正双向并发不混淆；双向两腿须有可证明的时间重叠。
- 单向与双向门限独立，工具与 NIC 门限独立，无门限只测量。
- 字节读取失败、接口不存在、计数复位、冻结、低覆盖、真实低速及工具接收失败分别验证。
- 可信低速必须保持 RATE_FAIL；不能因为工具数字较高而启用兜底。兜底不得把 sender、单流末行或旧 server 日志当作接收汇总。
- 双向一腿失败/丢失结果、混合来源、两腿工具有效但无工具门限，不得错误显示双向合计 PASS。
- 升级前内环文件可迁移；内环/子网互相误导入均拒绝且不改已有配置。
- 网络请求在执行后响应丢失、刷新/重连、重复停止、进程异常退出和 ADB 断开，均验证状态与资源归属。
- 32 网口时页面主体高度受控、批量修改可预期，排序/筛选不改变选中项身份。

## 9. 本机证据与资料

## 10. 实现基线与仍未验收的部分

第 8 节 1–5 步已落地。回归基线：`cargo fmt --check`、`cargo test --locked`（Rust 724 项）、本机与 `x86_64-pc-windows-msvc` 两目标 `cargo clippy --all-targets -- -D warnings`、前端 `vue-tsc --noEmit` 与 293 项测试、`npm run build` 与 `npm run verify` 产物一致性，全部通过。

自动化覆盖的行为（`src/inner/tests.rs`、`ui/src/**/inner.test.ts`）：

- 没有任何 agent、以及配置了但未被勾选链路引用的 agent，都能只跑本机。
- 计划按网口顺序展开，双向是一个含两腿、两端口的单元；两次顺序单向与双向并发在计划里就是不同条数。
- 单向与双向门限独立，工具与 NIC 门限独立，无门限只测量；严格模式不接受工具门限，未勾双向不接受合计门限。
- 可信低速保持 RATE_FAIL，不因工具数字更高而兜底；兜底不取 sender、单流末行或缺 `[SUM]` 的多流汇总。
- 混合来源、缺腿、两腿工具有效但无工具门限，都不会给出双向合计 PASS。
- 计数复位、冻结、低覆盖、真实低速各自映射到不同原因码；冻结加可信非零工具流量才算计数器不适配的证据。
- 板侧统计接口与 LAN 地址解耦，指定不存在的接口提前报错；桥与成员口只列候选、从不相加。
- v1 文件可迁移且不变成双向并发，更高版本拒绝导入；内环/子网互相误导入都拒绝且不改已有配置。
- 排序与批量不改变选中项身份，批量不复制电脑/网卡/源 IP。

**仍未验收**，需要真机补齐：

- 双向并发两腿在真实链路上的重叠窗口、板侧与 PC 的 client/server 资源占用与回收。
- 工具兜底在已知计数器不适配机型上的实际表现，以及多机型统计接口的选择结论。
- 32 条网口规模下的端到端执行时间与页面表现。
- 执行中断线/重连、ADB 拔出、进程异常退出时的状态与资源归属。
