2网口与策略

端接口名角色IPv4协商速率网关 作为接收端：RX 门限作为发送端：UDP -b作为发送端：UDP -l

RX 门限两种写法都行：1800 = 1800Mbps；90% = 该网卡协商速率的 90%， 每个单元开跑前按重扫到的协商速率换算，算式会出现在「预览任务」的提示里。 这里填的 UDP -b / -l 覆盖执行区的全局档位。

3测试矩阵

默认全不选。表头里的小勾选框整列开关，勾一下全开、再勾一下全关。每个要跑的组合至少保留一个方向、协议和 IP 版本。

双向门限只在勾了「双向」时生效，留空就沿用「网口与策略」里的 RX 门限。 半双工介质（Wi-Fi、部分 USB 网卡）双向同时灌包时，两个方向抢同一段介质时间， 每个方向拿到的只有单向的一部分——拿单向门限去卡双向必然判成 RATE_FAIL， 而那是配置出来的失败、不是测出来的。典型写法：单向 2000，双向两格各填 1000。 它按配对填而不是按网卡：同一块 RNDIS 口，和 Wi-Fi 组双向、和 SGMII 组双向， 能收到的速率完全不是一个量级，挂在网卡上只能填一个数，必然有一组是错的。 两个方向分开是因为半双工链路的两个方向本来就能差很远。只填绝对 Mbps，不收百分比—— 百分比要按单块网卡的协商速率换算，而那跟「这两块口凑在一起并发时能跑多少」没有关系。

4执行

空格或逗号分隔多个档位，TCP -w / -P 与 UDP -b / -l / -w 都会逐档各跑一轮 （UDP 三项取组合：2 档 -b × 2 档 -l × 2 档 -w = 8 个单元，跑之前用「预览任务」看一眼总数）。 按网口填写 UDP -b 后，该发送端固定使用网口值；留空的发送端继续扫描全局档位。

不勾「裁剪」时，填多少就发多少——想看链路在超额灌包下的表现就保持不勾。勾上后超过整条路径可信上限的档位会被自动压到上限，按网口单独指定的 -b 不受影响。
